# Mermaid Diagram Editor & Exporter

**Date:** 2026-08-24  
**Status:** Draft  
**Location:** `~/ai-projects/mermaid-diagram-editor/`

## Overview

A browser-based mermaid diagram editor with live preview, multi-tab support, local storage persistence, and PNG/SVG export capabilities. Built with npm and deployed to GitHub Pages via GitHub Actions.

## Goals

- Provide a simple, standalone tool for creating and exporting mermaid diagrams
- Support live preview with syntax-highlighted editor
- Enable saving multiple diagram sessions locally
- Export diagrams as PNG and SVG
- Support light/dark themes
- Deploy easily to GitHub Pages

## Technology Stack

### Build Tooling
- **Vite** - Fast development server and production build tool
- **Node.js/npm** - Package management with pinned dependencies

### Core Libraries
- **Mermaid.js** - Diagram rendering engine (pinned to latest stable)
- **Monaco Editor** - Code editor with syntax highlighting (VS Code's editor)
- **html-to-image** - Convert rendered diagrams to PNG
- **FileSaver.js** - Handle file downloads

### Deployment
- **GitHub Actions** - Automated build and deployment workflow
- **GitHub Pages** - Static site hosting

## Architecture

### Component Breakdown

#### 1. Application State Manager (`app.js`)
**Responsibilities:**
- Manages global application state (current tab ID, theme preference, layout mode)
- Coordinates communication between modules
- Handles UI control events (theme toggle, panel expand/collapse, new/save/delete tabs)
- Implements debounced auto-save (500ms delay after typing stops)
- Initializes application on page load

**Key State:**
```javascript
{
  currentTabId: string,
  theme: 'light' | 'dark',
  layoutMode: 'split' | 'editor-full' | 'preview-full'
}
```

#### 2. Editor Module (`editor.js`)
**Responsibilities:**
- Initialize Monaco Editor instance
- Configure mermaid syntax highlighting
- Emit change events when code is edited
- Support undo/redo, find/replace
- Maintain per-tab editor states

**API:**
```javascript
- initEditor(container) → editor instance
- loadCode(code) → void
- getCode() → string
- onChange(callback) → void
```

#### 3. Preview Module (`preview.js`)
**Responsibilities:**
- Initialize Mermaid.js with theme configuration
- Render mermaid diagrams in preview panel
- Handle parse errors gracefully
- Re-render on code changes
- Expose rendered SVG for export

**API:**
```javascript
- initPreview(container) → void
- renderDiagram(code) → Promise<void>
- setTheme(theme) → void
- getSvgElement() → SVGElement
```

#### 4. Storage Module (`storage.js`)
**Responsibilities:**
- Wrap browser LocalStorage API
- Serialize/deserialize tab data as JSON
- Auto-save current tab on code changes
- Manual save with updated name and timestamp
- Load all tabs on app initialization
- Handle storage quota errors

**Data Schema:**
```javascript
{
  tabs: [
    {
      id: string,           // UUID
      name: string,         // User-defined or auto-generated
      code: string,         // Mermaid diagram code
      createdAt: timestamp,
      updatedAt: timestamp
    }
  ],
  currentTabId: string,
  theme: 'light' | 'dark',
  layoutMode: 'split' | 'editor-full' | 'preview-full'
}
```

**API:**
```javascript
- saveTabs(tabs) → void
- loadTabs() → tabs[]
- saveCurrentTab(tab) → void
- savePreferences({theme, layoutMode}) → void
- loadPreferences() → {theme, layoutMode}
```

#### 5. Export Module (`export.js`)
**Responsibilities:**
- Export rendered diagrams as PNG (2x resolution for clarity)
- Export rendered diagrams as SVG with inlined styles
- Generate appropriate filenames with timestamps
- Handle export errors gracefully

**API:**
```javascript
- exportPNG(svgElement, filename) → Promise<void>
- exportSVG(svgElement, filename) → Promise<void>
```

**Filename Format:**
- `{diagram-name}-{YYYY-MM-DD}.png`
- `{diagram-name}-{YYYY-MM-DD}.svg`

#### 6. Tabs Module (`tabs.js`)
**Responsibilities:**
- Render tab bar UI with close buttons
- Create new blank or template-based tabs
- Switch between tabs (load code, update preview)
- Delete tabs (prevent deleting last tab)
- Rename tabs inline

**API:**
```javascript
- renderTabBar(tabs, currentId) → void
- createTab(template?) → tab
- switchTab(tabId) → void
- deleteTab(tabId) → void
- renameTab(tabId, newName) → void
```

#### 7. Templates Module (`templates.js`)
**Responsibilities:**
- Provide sample mermaid diagrams for common diagram types
- Render template picker dialog
- Create new tabs from selected templates

**Template Types:**
- Flowchart
- Sequence diagram
- Class diagram
- State diagram
- Entity-Relationship diagram
- Gantt chart
- Pie chart
- Git graph

## Data Flow

### Application Initialization
1. Load theme preference from localStorage → apply CSS class to document
2. Load saved tabs from localStorage (or create default tab with welcome diagram)
3. Initialize Monaco editor with first tab's code
4. Initialize Mermaid.js with current theme
5. Render initial preview
6. Set up event listeners for UI controls and editor changes

### User Types in Editor
1. User types → Monaco editor emits change event
2. App debounces for 500ms (prevent excessive renders)
3. After debounce period:
   - Update preview module → re-render mermaid diagram
   - Update storage module → auto-save current tab to localStorage

### User Exports Diagram
1. User clicks "Export PNG" or "Export SVG" button
2. Export module receives rendered SVG element from preview
3. **PNG:** html-to-image converts SVG to canvas → blob → triggers download
4. **SVG:** Clone SVG node, inline styles, serialize to string → triggers download
5. Downloaded file named `{tab-name}-{date}.{png|svg}`

### User Switches Tabs
1. User clicks tab in tab bar
2. Tabs module updates app state with new currentTabId
3. Editor module loads new tab's code
4. Preview module re-renders diagram for new code
5. No auto-save triggered (just loading existing content)

### User Toggles Dark Mode
1. User clicks theme toggle button
2. App updates document CSS class (`light-theme` / `dark-theme`)
3. Mermaid.js re-initialized with new theme configuration
4. Preview re-renders all diagrams with new theme
5. Theme preference saved to localStorage

### User Expands Panel
1. User clicks expand button on editor or preview panel
2. App updates layoutMode state to `editor-full` or `preview-full`
3. CSS class applied to hide other panel
4. Expanded panel takes full viewport width
5. Click collapse button to restore `split` mode

### User Creates New Tab
1. User clicks "New Tab" or "New from Template"
2. If template: show template picker dialog
3. Tabs module creates new tab object with UUID
4. Add tab to tabs array in storage
5. Switch to new tab (triggers tab switch flow)

### User Deletes Tab
1. User clicks close button on tab
2. If last tab: show warning, prevent deletion
3. Remove tab from tabs array in storage
4. Switch to previous or next tab
5. Re-render tab bar

## Error Handling

### Mermaid Parse Errors
- Wrap `mermaid.render()` in try-catch
- Display error message in preview panel with red border
- Show line number and error description when available
- Preserve previous valid diagram until user fixes syntax
- Clear error state when valid code is entered

### Storage Quota Exceeded
- Wrap `localStorage.setItem()` in try-catch
- Catch `QuotaExceededError` exception
- Show toast notification warning user
- Suggest deleting old tabs or exporting diagrams to free space
- App remains functional, just cannot save additional data

### Export Failures
- **PNG Export:** Catch html-to-image errors, show error toast with details
- **SVG Export:** Validate SVG element exists before serialization
- **Download Blocked:** Inform user to allow downloads in browser settings

### Missing Dependencies (CDN/Network Failures)
- Show loading spinner while Monaco and Mermaid load
- If CDN fails after timeout, display error message with retry button
- Graceful degradation: fall back to plain textarea if Monaco fails to load
- Log errors to console for debugging

### Corrupted LocalStorage
- Wrap `JSON.parse()` in try-catch on app initialization
- If parsing fails, log error to console
- Clear corrupted data and start fresh with default welcome tab
- User loses saved tabs but app remains functional

## Build & Deployment

### Development
```bash
npm install           # Install dependencies
npm run dev          # Start Vite dev server (http://localhost:5173)
```

### Production Build
```bash
npm run build        # Build to dist/
npm run preview      # Preview production build locally
```

### GitHub Actions Workflow (`.github/workflows/deploy.yml`)
```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches: [ main ]
  workflow_dispatch:

jobs:
  build-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
      
      - name: Install dependencies
        run: npm ci
      
      - name: Build
        run: npm run build
      
      - name: Deploy to GitHub Pages
        uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

**Deployment Trigger:** Push to `main` branch  
**Output:** Static files in `dist/` deployed to `gh-pages` branch  
**URL:** `https://<username>.github.io/mermaid-diagram-editor/`
